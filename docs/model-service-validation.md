# 模型协议验证

模型配置与能力逻辑集中在 `lib/llm/`。列表请求、同步生成、流式生成和结构化输出通过共享适配器完成；可用性检查也复用列表适配器，避免不同入口的鉴权行为不一致。

## 自动化覆盖

- 使用模拟 HTTP 响应覆盖内置供应商、兼容网关和本地无认证服务的请求地址、鉴权、消息、推理增量、用量和结构化响应。
- Claude 模型列表使用原生版本头与 `x-api-key`，生成走兼容接口。元数据明确的思考档位和窗口优先于型号推断；未知型号保留默认。
- 新增、编辑、切换、删除模型配置，以及旧会话所选服务已移除后的恢复行为均有回归；凭据省略保留、显式清除，上游错误不回显。
- 列表不支持、型号未确认、超时、授权失败返回不同结果；探测列表不执行生成请求。

这些测试证明应用协议与流程，不能证明所有真实账号、区域、套餐或模型均可用，也不能证明抽取和问答质量。测试使用临时配置与模拟服务，不需要真实 Key。

## 可选真实服务复测

```bash
pnpm exec tsx scripts/model-service-smoke.mts /tmp/weave-model-service-smoke.json
pnpm exec tsx scripts/answer-quality-benchmark.mts /tmp/weave-answer-quality.json
```

上述命令仅在明确需要时执行：只读已有配置，发送固定或合成测试内容，不读取个人知识正文，但会消耗真实模型额度。输出会含实际型号与服务主机等运行信息，应保留在本机；不提交凭据、个人配置或上游错误正文。

本轮发布整理不运行这些真实调用，自动化结果和已知边界见 [验收记录](validation.md)。
