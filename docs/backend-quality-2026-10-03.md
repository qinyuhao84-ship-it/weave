# 后端品质修复记录（2026-10-03）

本记录描述临时测试库和模拟模型上的协议、持久化与索引验证。未调用真实模型；这些结果不证明真实回答质量或事实准确度。

## 修复

- 非流式模型响应与 SSE 使用相同的完成边界：只有 `stop` 和 `length` 是可识别的终态，且正文必须非空。`length` 保留已有正文并返回截断标记，供结构化输出精简重试；内容过滤拒绝、缺少或未知终态、空正文均按失败处理。连接测试也要求有效正文。
- 失败、取消和仍在运行的助手正文继续保存在会话里供用户查看，但不进入后续问答或摘要输入。失败收尾保留已经校验的正文；旧版摘要保留在 SQLite，`legacy` 摘要只有在水位线可核验且未覆盖不完整回答时才可用于上下文。新摘要记录 `complete` 策略。
- 重复 ID 的 Markdown 文件进入冲突隔离，不修改正文，也不发布相关全文、双链和图谱证据；冲突记录、会话归档、人工裁决和重定向均保留。修正 ID 后，重建索引先释放该文件原活跃 ID 的路径所有权，再发布新 ID；路径 watcher 只读取活跃索引行。

## 数据库迁移与保留验证

新增迁移 `drizzle/0012_history_policy_and_active_paths.sql`：旧摘要的 `history_policy` 默认设为 `legacy`；`idx_pages_file_path` 改为仅约束 `status = 'active'` 的部分唯一索引。旧身份行可保留原路径，当前活跃身份仍不能重复占用路径。

`tests/migration-history-policy.test.ts` 在临时 SQLite 文件中执行 0000–0011 迁移、写入会话、消息、用户裁决、旧摘要和活跃页面，再执行 0012。验证会话字段、裁决内容、摘要正文与水位线原值保持不变，旧摘要被标为 `legacy`；同路径的删除历史行可以共存，而第二个活跃行仍触发唯一约束。未连接或改写个人数据库。
